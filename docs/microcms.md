# microCMSの接続準備

既存8問の移行は完了しています。問題データはmicroCMSの公開済みコンテンツから読み込みます。ローカルで連携を確認済みで、公開サイトへの反映は別途必要です。

## 1. サービスを作成する

ChromeのmicroCMS管理画面でサービスを作成します。

| 項目       | 設定                                                   |
| ---------- | ------------------------------------------------------ |
| サービス名 | `CYBER FIRST STEP`                                     |
| サービスID | 空いている英小文字・数字・ハイフンのID。設定後に控える |

有料プランを選ぶ必要はありません。利用規約の確認や契約に関する操作は管理者自身で行ってください。

## 2. 接続先のAPIを作成する

| 項目             | 設定                                                              |
| ---------------- | ----------------------------------------------------------------- |
| API名            | `問題`                                                            |
| エンドポイント   | `questions`                                                       |
| APIの型          | リスト形式                                                        |
| 最初のフィールド | フィールドID `title`、表示名 `問題名`、種類「テキストフィールド」 |

接続確認だけならコンテンツを登録・公開する必要はありません。空のAPIでも成功します。
`title` だけで問題を動かすことはできません。問題の移行時に必要な入力項目を追加します。

## 3. 読み取り専用のAPIキーを設定する

APIキーの設定は次の最小権限にします。既存キーがある場合は、その権限を確認してください。

| 権限                               | 設定           |
| ---------------------------------- | -------------- |
| デフォルト権限                     | すべてオフ     |
| `questions` の個別権限             | `GET` のみオン |
| 下書き・公開終了コンテンツの全取得 | オフ           |
| `POST`・`PUT`・`PATCH`・`DELETE`   | オフ           |
| マネジメントAPI                    | すべてオフ     |

キーはチャット・スクリーンショット・リポジトリ・ブラウザ側のJavaScriptに貼らないでください。
接続確認コマンドはGETだけを実行します。キーの書き込み権限が無効かどうかは管理画面で確認してください。

## 4. ローカルの環境変数を設定する

プロジェクト直下の `.env.local` に、次の3項目を追加します。
すでにある `CTF_SESSION_SECRET` や他の設定は残してください。
`.env.example` は項目名の見本で、実際のキーは書き込みません。

```dotenv
MICROCMS_SERVICE_DOMAIN=作成したサービスID
MICROCMS_ENDPOINT=questions
MICROCMS_API_KEY=管理画面で確認したAPIキー
```

`MICROCMS_SERVICE_DOMAIN` は `https://` や `.microcms.io` を含めないIDだけです。
`.env.local` はGitの対象外です。共有フォルダへのコピーにも含めないでください。

## 5. 接続確認

```sh
npm run check:microcms
```

成功時は `microCMS接続OK：公開コンテンツ0件。` のように件数だけを表示します。
問題の本文・答え・ID・APIキーは表示しません。
設定不足や通信失敗の場合は終了コード1で停止します。

| 結果                   | 確認する点                                         |
| ---------------------- | -------------------------------------------------- |
| 環境変数の設定エラー   | 名前と値を確認。値をチャットへ貼る必要はありません |
| HTTP 401・403          | キーが有効か、`questions` のGETが許可されているか  |
| HTTP 404               | サービスIDとエンドポイントが正しいか               |
| HTTP 429               | 少し待ってから再実行。連続実行しない               |
| 応答形式のエラー       | APIがリスト形式か                                  |
| 通信失敗・タイムアウト | 接続先、ネットワーク、microCMSの稼働状況           |

## 接続処理の安全性と範囲

- サーバー用の `server/microcms.mjs` だけでキーを扱います。ブラウザ用のAPIや代理取得URLは作成していません。
- 宛先は検証したサービスIDの `https://<ID>.microcms.io` に固定し、リダイレクトは拒否します。
- 接続確認は `GET` で1件のIDだけを要求し、取得した内容は返さず件数だけを返します。問題取得は最大32問の全件取得を検証し、途中で切れた一覧は拒否します。
- 通信と応答本文の読み取りを5秒で打ち切ります。接続確認は64KiB、問題取得は1MiBを上限にします。
- 外部のエラー本文や例外をログへ流さず、固定した案内文に置き換えます。
- 新しい依存パッケージ、DB、管理用の公開エンドポイントは追加していません。CSPの画像配信先に `https://images.microcms-assets.io` だけを追加しています。ブラウザからのCMS API接続は許可していません。

## 問題の編集と確認

microCMSの「問題」で編集する問題を選び、文章・正解・ヒント・解説・素材を入力して「公開」します。「問題の形式・素材」は1つ選択します。画像はフォームの画像欄からアップロードします。

既存画像は移行時の画像パスを参照しています。アップロード画像を選択するとそちらを優先します。既存画像パスの許可一覧はサーバーに保持します。

問題番号は1からの連番、最大32問です。公開後に次のコマンドで全件の形式と既存画像を検証できます。

```sh
npm run check:microcms:content
```

起動・設定チェック・ビルドには、接続先・読み取りキー・進捗署名鍵が必要です。通常の問題編集では再ビルドやコード変更は不要です。

- 公開済みの問題だけを使い、必須項目・形式・連番・正解・画像URLを検証します。画像は正規の配信ホストのPNG・JPEG・WebP・AVIFだけを許可します。
- 問題の取得結果はインスタンス内で30秒保持します。更新反映まで最大30秒程度かかります（インスタンスや通信状況によって異なります）。
- 更新後の内容が同じなら既存進捗を維持します。問題文・正解・素材など内容が変わった場合は全体の進捗をリセットします。CMSの更新日時だけではリセットしません。
- 古い画面から別版の問題に回答した場合は、再読み込みを案内します。
- CMSの内容が不正・空・取得不能の場合は503で停止し、別のローカル問題へ自動で切り替えません。失敗後5秒は再取得を抑制します。
