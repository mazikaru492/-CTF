# 運用・編集ガイド

普段は問題設定・配色・配置だけを編集します。回答判定やCookieのコードを変更する必要はありません。

## 問題文・答え・ヒントを変更する

1. `content/questions.json` を開き、変更したい問題の `id` または `title` を探します。
2. 必要な項目を編集します。JSONではキーと文章をダブルクォートで囲みます。最後の項目に余分なカンマを付けないでください。
3. `npm run check` を実行します。間違いがあれば問題番号と項目名を表示します。
4. `npm run dev` で起動し、スマホ幅320・390・430pxを基準に問題、２つのヒント、正解、不正解、解説を確認します。
5. `npm test` と `npm run build` を実行します。

変更した問題がすでに正解・学習済みの場合は、結果画面でローカルの進捗をリセットして確認してください。

### 問題の項目

| 項目          | 用途                                          |
| ------------- | --------------------------------------------- |
| `id`          | 問題番号。配列の順番に１からの連番            |
| `kind`        | 操作・素材の形式。下の表から選ぶ              |
| `category`    | 問題一覧の分野ラベル                          |
| `title`       | 問題名                                        |
| `subtitle`    | 問題一覧の短い説明                            |
| `instruction` | 解くための問題文                              |
| `material`    | 画像・暗号・記録などの素材                    |
| `answer`      | 答え。100文字以内の半角大文字、前後の空白なし |
| `hints`       | 第１段階、第２段階の順に２つの文章            |
| `explanation` | 答えにたどり着く理由                          |
| `learning`    | 手法と利用場面を含む学習説明                  |

`answer`・`hints`・`explanation`・`learning` は、最初の問題一覧には配信しません。`material` は問題を解くための公開素材なので、非公開にしたい情報を追加しないでください。

### 素材の形式

| `kind`    | `material` の項目                                                             | 操作                                                                        |
| --------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `cipher`  | `cipher`                                                                      | 英字を１文字前へ戻す暗号。Aの前はZ                                          |
| `ascii`   | `numbers`                                                                     | 65〜90の整数を英字に変換                                                    |
| `image`   | `image`, `alt`, `textClue`, `textDetail`                                      | 画像拡大と文字での手がかり                                                  |
| `compare` | `before`, `after`, `textClue`, `textDetail`                                   | 変更前後の画像切り替え。必要に応じ `beforeAlt`, `afterAlt` で画像説明も変更 |
| `logs`    | `logs` の各行に `time`, `device`, `result`、`devices` の各端末に `id`, `code` | ログを読み、端末を選ぶ                                                      |
| `records` | `current` にIDの配列、`backup` の各記録に `id`, `code`                        | 一覧とバックアップの照合                                                    |
| `order`   | `cards` の各カードに `id`, `time`, `event`, `letter`                          | 時刻順に並べ替える                                                          |
| `final`   | `image`, `alt`, `textClue`, `textDetail`, `cipher`, `rule`                    | 鍵の画像と規則を組み合わせる                                                |

端末・記録・カードのIDは半角英数字、ハイフン、アンダースコアが使用できます。カードの時刻は `09:03` のような24時間表記、文字は英大文字１文字です。英字対応表は共通表示なので変更不要です。

たとえば数字の問題の素材は次の形です。

```json
{
  "numbers": [67, 89, 66, 69, 82]
}
```

既存の同じ `kind` の問題を複製すると、素材の形式を間違えにくくなります。異なる操作を新しく作る場合だけ `public/scripts/materials.js` と検証ルールを変更します。

## 画像を変更する

1. 新しい画像を `public/assets/` に置きます。対応形式はSVG・PNG・JPEG・WebP・AVIFです。
2. 問題設定の `image`、または `before` / `after` を `/assets/新しい画像.png` のように変更します。
3. `alt`（画像説明）、`textClue`、`textDetail`、ヒント、答えも実際の画像と合わせます。
4. `npm run check` でパスを確認し、スマホで拡大して文字を読めるか確認します。

設定チェックは画像の存在を確認しますが、画像中の文字の正しさは判定しません。解読して答えと一致することを目視で確認してください。

## 問題を追加・差し替え・削除する

追加は `questions` 配列の末尾に問題を複製し、次の連番を付けます。問題数・前後の矢印・進捗・未完了数は自動で変わります。Cookieの容量を保つため上限は32問です。

同じIDの答えや内容を別の問題に入れ替える場合は、ファイル先頭の `progressVersion` を１増やします。古い正解記録が新しい問題に引き継がれるのを防ぐため、公開後は利用者の進捗がリセットされます。誤字や配色だけの修正では増やしません。

削除・並べ替えはIDを１から連番に整え、`progressVersion` も増やしてください。問題数を変更した場合も、古いCookieは新しい数に合わないため進捗がリセットされます。

## 配色・文字サイズ・配置を変更する

- `public/theme.css`：明るい・暗い背景の共通色、カードの色、フォント、トップの小見出しサイズ。`--hero-label-size` の `1.0625rem` は通常17px相当です。
- `public/styles.css`：余白、各欄やボタンの大きさ、スマホの配置。スマホは `@media (max-width: 700px)`、問題一覧の開閉表示は1023px以下です。
- `public/index.html`：ヘッダー・フッターと固定ダイアログの文章。
- `public/scripts/pages.js`：トップ・問題・結果・紹介ページの表示。HTMLは改行して整形しています。
- `public/scripts/materials.js`：画像切り替え、端末選択、並べ替えの操作。
- `public/scripts/dialogs.js`：画像拡大・確認ダイアログ。通常の文章変更では触りません。
- `public/scripts/ui.js`：問題のアイコン、マスコット、正解・不正解の演出。
- `public/app.js`：通信・画面切り替え・回答提出。通常の問題変更では触りません。

同じCSS指定を末尾に足すのではなく、検索して既存の指定を修正してください。変更後は `npm run format` で整形できます。

## 確認コマンド

| コマンド                | 確認するもの                                 |
| ----------------------- | -------------------------------------------- |
| `npm run check`         | 問題設定・画像パス                           |
| `npm test`              | 判定・Cookie・検証ルール・問題数変更         |
| `npm run test:mobile`   | スマホ縦横・文字拡大・キーボード表示時の操作 |
| `npm run test:feedback` | 正解・不正解、配色、動きを減らす設定         |
| `npm run test:devices`  | タブレット・PCも含む追加確認                 |
| `npm run build`         | 設定確認後、配信用ファイルを `dist/` に生成  |
| `npm run format:check`  | 自動整形の確認                               |

ブラウザテストには、初回だけ `npx playwright install chromium webkit` が必要です。ブラウザのエミュレーションでの検証なので、公開前には実機でも確認してください。

## 開発・公開・秘密値

`npm run dev` は問題設定やサーバーの保存を監視します。再起動後、ブラウザを更新すると変更を確認できます。ローカルの署名鍵は `.env.local` で維持され、Gitに入りません。鍵を変更・削除するとローカルの進捗は無効になります。

公開時はVercelの環境変数に `CTF_SESSION_SECRET` を設定します。`content/` と `server/` はサーバー専用、`public/` だけがブラウザへ配信されます。秘密値や答えの設定ファイルを `public/` に置かないでください。

`dist/` は毎回作り直すビルド結果です。編集・素材の追加は必ず元の `public/` に行います。公開手順・計測・素材の出典と制限は [公開運用の詳細](operations.md) を参照してください。
