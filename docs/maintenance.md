# 運用・編集ガイド

問題文・答え・ヒント・解説・素材はmicroCMSで管理します。

## 問題を変更する

1. microCMSの「問題」から対象を開きます。
2. 問題名・問題文・正解・ヒント1と2・解説・学習内容を編集します。
3. 「問題の形式・素材」で暗号・画像・記録などのブロックを1つ選び、素材を入力します。
4. 「公開」を押します。参照先のサイトには通常30秒程度で反映されます。
5. スマホで問題・素材・ヒント・正答・誤答・解説を確認します。`npm run check` で入力形式も確認できます。

正解は100文字以内の半角大文字、問題番号は1からの連番で最大32問です。問題一覧の初回取得には正解・ヒント・解説・学習内容を含めません。素材は利用者に表示されるため、管理用の秘密情報を入れないでください。

## 画像を変更する

1. 素材の画像欄からPNG・JPEG・WebP・AVIFをアップロードして選択します。
2. 画像説明・文字の手がかり・ヒント・答えも実際の画像に合わせます。
3. 公開後にスマホで表示・拡大・文字の読み取りを確認します。

既存画像は `public/assets/` を参照しています。CMS側で新しい画像を選択すると、その画像を優先します。使用中の画像ファイルを削除しないでください。形式の検証では画像中の文字の正しさまでは判定しません。

## 問題を追加・差し替え・削除する

管理画面で追加・編集・公開終了を行い、公開する問題の番号を1からの連番にそろえます。問題数・前後の移動・進捗表示は自動で変わります。

問題文・答え・素材などを変更すると全体の進捗は自動でリセットされます。変更前の画面から送信すると再読み込みを案内します。問題内容が同じ場合は既存進捗を維持します。

コード内のテスト用データは回帰確認のためのものです。通常の問題編集はmicroCMSで行います。接続設定は [microCMS接続ガイド](microcms.md) を参照してください。

## 配色・文字サイズ・配置を変更する

- `public/theme.css`：白い背景の共通色、カードの色、フォント、トップの小見出しサイズ。`--hero-label-size` の `1.0625rem` は通常17px相当です。背景の切り替えはありません。
- `public/styles.css`：余白、各欄やボタンの大きさ、スマホの配置。スマホは `@media (max-width: 700px)`、問題一覧の開閉表示は1023px以下です。
- `public/index.html`：ヘッダー・フッターと固定ダイアログの文章。
- `public/scripts/pages.js`：トップ・問題・結果・紹介ページの表示。HTMLは改行して整形しています。
- `public/scripts/materials.js`：画像切り替え、端末選択、並べ替えの操作。
- `public/scripts/dialogs.js`：画像拡大・確認ダイアログ。通常の文章変更では触りません。
- `public/scripts/ui.js`：問題のアイコン、マスコット、正解・不正解の演出。
- `public/app.js`：通信・画面切り替え・回答提出。通常の問題変更では触りません。

同じCSS指定を末尾に足すのではなく、検索して既存の指定を修正してください。変更後は `npm run format` で整形できます。

## 確認コマンド

| コマンド                | 確認するもの                                 |
| ----------------------- | -------------------------------------------- |
| `npm run check`         | 問題設定・画像パス                           |
| `npm test`              | 判定・Cookie・検証ルール・問題数変更         |
| `npm run test:mobile`   | スマホ縦横・文字拡大・キーボード表示時の操作 |
| `npm run test:feedback` | 正解・不正解、配色、動きを減らす設定         |
| `npm run test:devices`  | タブレット・PCも含む追加確認                 |
| `npm run build`         | 設定確認後、配信用ファイルを `dist/` に生成  |
| `npm run format:check`  | 自動整形の確認                               |

ブラウザテストには、初回だけ `npx playwright install chromium webkit` が必要です。ブラウザのエミュレーションでの検証なので、公開前には実機でも確認してください。

## 開発・公開・秘密値

`npm run dev` は問題設定やサーバーの保存を監視します。再起動後、ブラウザを更新すると変更を確認できます。ローカルの署名鍵は `.env.local` で維持され、Gitに入りません。鍵を変更・削除するとローカルの進捗は無効になります。

公開時はVercelの環境変数に `CTF_SESSION_SECRET` とmicroCMSの接続先・読み取りキーを設定します。`server/` はサーバー専用、`public/` だけがブラウザへ配信されます。秘密値や答えの設定ファイルを `public/` に置かないでください。

`dist/` は毎回作り直すビルド結果です。編集・素材の追加は必ず元の `public/` に行います。公開手順・計測・素材の出典と制限は [公開運用の詳細](operations.md) を参照してください。
